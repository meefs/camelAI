Prompt Schedules

Send a message to a thread and let the agent decide what to do. Best for reminders, reports, and open-ended work.

Deterministic Automations

Run code directly through Cloudflare Workflows. Best for exact side effects, durable sleeps, retries, and integrations.

Workspace Boundary

All schedules, source, versions, and tool access are scoped to the current workspace.

Schedule Flow

This mirrors the Cloudflare Agents SDK pattern: many schedules in SQLite, one Durable Object alarm set to the earliest next run.

Create

The agent calls create_deterministic_automation with source and a five-field UTC cron expression.

Validate

The Worker Loader checks syntax and confirms the module exports AutomationWorkflow.

Alarm

WorkspaceCronDO stores the next run and schedules its DO alarm for the earliest enabled job.

Start Workflow

The alarm creates a Dynamic Workflow instance tagged with source version and schedule context.

Script Contract

import { WorkflowEntrypoint } from "cloudflare:workers";

export class AutomationWorkflow extends WorkflowEntrypoint {
  async run(event, step) {
    const payload = event.payload;

    const result = await step.do("deterministic unit", async () => {
      return {
        automationId: payload.automationId,
        scheduledFor: payload.scheduledFor,
        trigger: payload.trigger
      };
    });

    return result;
  }
}

Why Source Versioning Matters

Workflow instances can sleep and resume much later. Each instance is tagged with the source version that created it, so a later agent edit does not alter code already running inside a durable workflow.
